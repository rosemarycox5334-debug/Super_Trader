# Super Trader —— A 股 AI 多 Agent 交易平台 设计文档

> 版本：v0.1（设计稿）
> 日期：2026-11-06
> 底座：DeepSeek Harness（LLM Agent 运行时）
> 复用：现有 `super_trader` 规律挖掘与独立验证引擎
> 功能参考：`功能参考/bilibili_无名游资_Agent资料`（AI 多 Agent 量化投研系统 V2.0 架构）

---

## 0. 一句话定位

把「无名游资」公开资料里那套 **L0→L6 七层多 Agent 量化投研流水线**，落在
**DeepSeek Harness** 这个 LLM Agent 运行时之上，交易员每天只需要看三样东西：
**盘前预案、盘中盯盘信号、收盘复盘**，其余由 Agent 团队自己研究、自己验证、自己风控、自己迭代。

本平台是**研究与决策支持系统**，不自动下单到实盘券商。所有「下单」默认进入
**纸面交易 / 模拟盘**，接入实盘需单独授权并通过三道放行门。

> 合规声明：所有结论都是历史频率与模型推断，不构成投资建议。A 股 T+1、涨跌停、
> 印花税 0.05% + 佣金、冲击成本均在验证层显式建模。

---

## 1. 为什么以 DeepSeek Harness 为底座

| 诉求 | Harness 提供 | 本平台在其上补什么 |
|---|---|---|
| 多 Agent 编排 | 会话 / 工具调用 / 子 Agent 调度 | 7 个固定岗位 Agent + 会议室协议 |
| 工具调用 | 文件读写、命令执行、HTTP、检索 | A 股数据工具、规律验证工具、风控工具 |
| 记忆 | 上下文 / 会话历史 | 情景记忆库 + 否定知识库（失败案例表） |
| 模型路由 | 多模型可切换 | 不同岗位用擅长的模型（专家团队 > 全能选手） |
| 可观测 | 执行日志 | 全链路审计 + 实验登记表（DSR/PBO 前提） |

**关键取舍**：Harness 只负责「让 Agent 能跑、能调工具、能留痕」；
**所有硬约束（风控、放行门、成本模型）用代码实现，不写进提示词**——
提示词会被模型「说服」，代码不会。

## 2. 整体架构：七层流水线

沿用参考资料主图（AI 多 Agent 量化投研系统 V2.0）的 L0–L6 分层。每层**必须有产出物**，
交给下一层做输入；没有产出实体就不算这一层完成。

```
┌─────────────────────────────────────────────────────────────────────┐
│ L6  策略迭代闭环   保留/加权 · 降权/淘汰 · 变异/新生 · Graveyard 墓园  │
│        ▲                                                      │       │
│        │ 下一代假设回流 L1                            偏误/归因 │       │
│ L5  监控与归因   Alpha 衰减 · 回测-实盘偏差 · 暴露漂移 · Brinson     │
│        ▲                                                              │
│ L4  执行与实时风控  执行层(TWAP/VWAP/集合竞价) · 硬约束 · KILL-SWITCH │
│        ▲                                                              │
│ L3  分级放行门   Gate1 扣费后有优势? · Gate2 摩擦真这么小? · Gate3 亏得起?│
│        ▲                                                              │
│ L2  独立量化验证  DSR · PBO · 参数扰动 · 分域回测 · T+1/涨跌停/成本     │
│        ▲                                                              │
│ L1  多 Agent 研究团队  研究/开发/红队/事实/记忆/组合风险/审查官/鬼点子  │
│        ▲                                                              │
│ L0  数据与特征基座  行情 · 基本面/事件 · 文本/舆情 · 宏观/另类(PIT对齐) │
└─────────────────────────────────────────────────────────────────────┘
```

**三条设计铁律**（来自参考资料，本平台强制执行）：

1. **研究与交易分离、建议与执行分离**——生成策略的 Agent 不许下单；下单的 Agent 不许改策略。
2. **每层有产出物**——证据链 / 验证报告 / 放行档位都是数据库里的实体记录。
3. **验证器必须独立**——L2 由代码跑，不由 L1 的 Agent 自评。同一批 Agent 自验证等于没验证。

## 3. L0 数据与特征基座

### 3.1 已有（复用现有 `super_trader`）

| 模块 | 职责 | 现状 |
|---|---|---|
| `data.py` | 日线读入 + 校验 + parquet 缓存 + 除权跳变识别 + 涨跌停/板块判定 | 已有，`data/cache/{个股,ETF,指数}/` 共 1.6 万+ 标的缓存 |
| `features.py` | ~50 个特征（趋势/波动/位置/量能/形态/缺口/日历/涨跌停） | 已有 |
| `universe.py` | 主流标的池（10 宽基 + 14 行业 + 14 ETF + 24 龙头） | 已有 |

### 3.2 待建（对标「256 维量化数据库」）

参考资料把数据维度从「只回测 K 线」扩到 **256 维多模态/多因子**，这是解决过拟合的核心。
分 11 组，按可获取性分阶段接入：

| 组 | 维度示例 | 来源 | 优先级 |
|---|---|---|---|
| 基础行情 | OHLCV、复权因子、振幅、换手 | 现有缓存 | ✅ 已有 |
| 游资资金 | 龙虎榜、营业部画像、席位 | 爬虫/数据商 | P1 |
| 公司事件 | 公告、停复牌、分红送转、解禁 | 公告源 | P1 |
| 财务估值 | PE/PB/股息率/ROE | 财报源 | P1（烟蒂股 Agent 必需） |
| 情绪面 | 淘股吧/股吧/热搜/拥挤度 | 爬虫 | P2 |
| 消息面 | 新闻、研报 | 新闻源 | P2 |
| 板块题材 | 概念强度、板块轮动、权重加速度 | 数据商 | P2 |
| 市场环境 | 涨停家数、情绪温度、两市成交 | 行情源 | P1 |
| 宏观另类 | 利率、汇率、外围指数（纳指等） | 宏观源 | P3 |

> **数据纪律（来自参考资料「先修数据，别先写 Agent」）**：
> PIT（Point-In-Time）对齐 + 退市/换月补齐 + 因子版本化。数据不干净，上层全是幻觉。
> 当前日期特征里月初/月末类**暂不用于实时信号**（会偷看未来观测到的日期）。

### 3.3 产出物
干净、可回溯、可复现的点时（PIT）数据面板 + 版本号，供 L1/L2 消费。

## 4. L1 多 Agent 研究团队（DeepSeek Harness 之上）

### 4.1 岗位设计（任务越单一越好）

参考资料核心经验：*「一个 Agent 处理的事情越多越差，注意力被稀疏了」*。故切成 8 个单一职责岗位：

| Agent | 单一职责 | 可用工具 | 不许做 |
|---|---|---|---|
| 市场研究 | 收集当日最重要数据、找机会、产出**可证伪假设** | 数据面板、检索、新闻/舆情 | 写代码、下单 |
| 策略开发 | 把假设写成**可复现代码**（入场/出场/仓位规则） | 代码执行、回测沙箱 | 下单 |
| 反方审计（红队） | 专职找漏洞：过拟合、幸存者偏差、成交不了的量 | 验证工具（只读） | 提新策略 |
| 事实验证 | 财报/公告数字必须查到**原文**，标注来源与日期 | 公告源、检索 | 下结论 |
| 记忆复盘 | 情景记忆 + 否定知识库；失败案例入库防重犯 | 记忆库读写 | 下单 |
| 组合与风险 | 决定权重与风险预算，**一票否决权** | 风控工具、组合优化 | 改策略逻辑 |
| 审查官 | 专查交易操作是否符合规范 | 审计日志（只读） | 交易 |
| 鬼点子 | 产出新鲜策略假设供选用 | 检索、数据面板 | 下单 |

### 4.2 「蒸馏人格」Agent（产品形态）

参考资料落地了几个人格 Agent，本平台抽象成**可插拔策略人格**，共享同一套 L0–L6 底座：

| 人格 | 内核判断函数（不是角色扮演） | 已知缺陷 |
|---|---|---|
| 烟蒂股（价值） | 只买「便宜到不像话、但仍真金白银分红」的票；靠股息 + 估值回归；按股息率每日轮动 | 牛市必然跑输（买便宜不买成长） |
| 巴菲特 | 用自身经验与核心理念判断市场，而非模仿形象 | 低换手、错过题材 |
| 低位首板（打板） | 位置 + 板块 + 大盘 + 形态 + 分时多条件打板；三档严苛度（最严≈月 3 次 / 中 / 频繁） | 情绪退潮期回撤大 |
| 淘股吧复盘 | 抓游资发言/战绩/交割单，做盘前预案 + 复盘 | 数据依赖爬虫稳定性 |

> **提示词哲学（参考资料最值钱的一段）**：要「是」，不要「像」。
> 不写「你是顶级交易员，每天盯盘到深夜」，而写**决策函数**：「你依据这三条事实做决策：①…②…③…」。
> 约束要**少而硬**，方向要**粗而准**；管得越细，模型越把算力烧在「看起来在做」上。

### 4.3 会议室机制（AI 会议室）

参考资料：不要让 20 个 Agent 轮流采访式发言（慢且失真）。正确做法：

1. **记忆复盘 Agent 先汇总**：把当天所有 Agent 的「新发现 + 新坑」整理成一份摘要。
2. **一进场拿全上下文**：各 Agent 进会议室直接拿到全部摘要，而非逐个等待发言。
3. **持续融合**：会议记录每天滚动更新，长期积累（参考资料提到 10 万字量级），取长补短。

### 4.4 产出物
可执行策略提案 + 证据链（假设、支持数据、反方意见、事实核验来源、建议权重）。

## 5. L2 独立量化验证引擎（代码，不由 Agent 自评）

直接复用并扩展现有 `super_trader` 的统计机制，这是本平台相对「只跑 K 线」最硬的护城河：

| 检验 | 现有模块 | 作用 |
|---|---|---|
| 二项检验 / Wilson 区间 | `stats.py` | 单标的方向优势显著性 |
| BH-FDR 多重检验校正 | `stats.py` | 压掉「跑一堆规则总有几个显著」的假阳性 |
| Newey-West HAC | `stats.py` / `evaluate.py` | 重叠窗口 + 横截面相关，独立单位回到「时间」 |
| 有效样本量 n_eff = n/h | `stats.py` | 修正 h 日前瞻的重叠 |
| 规格曲线（12 组设定） | `evaluate.py` | 结论不依赖单一参数选择 |
| 安慰剂检验 | `diagnose.py` | 真实晋级率 ÷ 安慰剂晋级率 = 真发现程度 |
| 时间顺序切分 + 边界净化 | `accuracy.py` / `personalize.py` | 杜绝未来函数 |

**待补（对标参考资料 L2）**：
- **DSR**（Deflated Sharpe Ratio）：按试验次数折减夏普，惩罚多次尝试。
- **PBO**（Probability of Backtest Overfitting）：组合对称交叉验证估计过拟合概率。
- **现实摩擦压力测试**：T+1、涨跌停买不进、印花税 0.05% + 佣金、滑点、冲击成本一次性全开。

### 5.1 产出物
带签名的**验证报告** + **可复现包**（参数、随机种子、样本外结果、实验登记编号）。

## 6. L3 分级放行门（三道 Gate，写成代码）

参考资料强调：**放行门写成代码，不是写成提示词**。

| Gate | 问题 | 判据（示例阈值，可配置） |
|---|---|---|
| Gate1 费后优势 | 扣完费率还有优势吗？ | 扣印花税+佣金+滑点后，方向优势仍显著（p、FDR 达标） |
| Gate2 执行摩擦 | 执行摩擦真这么小吗？ | 剔除次日一字涨停不可买入场景后，优势保留 ≥ X% |
| Gate3 小资金 | 小资金真实亏得起吗？ | 最大回撤、单日亏损在可承受区间；容量够小资金成交 |

通过才发放**放行额度与档位**（纸面 → 小资金 → 更高额度，逐级解锁）。

## 7. L4 执行与实时风控

### 7.1 执行层
TWAP / VWAP / 集合竞价、冲击成本预估、失败重试。**默认写入模拟盘**；实盘接口需单独授权。

### 7.2 硬约束（代码拦截，Agent 无权覆盖）

| 约束 | 默认值 | 说明 |
|---|---|---|
| 单票上限 | ≤ 5% NAV | 单一标的风险 |
| 单行业上限 | ≤ 15% NAV | 板块集中度 |
| 日亏熔断 | 日亏 2–3% 停止开仓 | 当日止损 |
| 回撤清仓 | 回撤 10% 降仓 / 20% 清仓 | 组合级止损 |
| KILL-SWITCH | 一键全停 | 异常/黑天鹅 |

### 7.3 产出物
合规成交记录 + 实时风险状态面板。

---

## 8. L5 监控与归因
- **Alpha 衰减监控**：规则/策略的优势是否随时间消退。
- **回测-实盘偏差归因**：模拟与纸面成交差在哪（滑点？涨停？信号延迟？）。
- **暴露漂移 + Brinson 归因**：收益来自选股还是择时，暴露是否偏离设计。

产出物：偏误与归因结论，回流 L6。

---

## 9. L6 策略迭代闭环
- **保留与加权**：持续有效的策略提权重。
- **降权与淘汰**：衰减的降权。
- **变异与新生**：由鬼点子 Agent 产出下一代假设，回流 L1。
- **Graveyard 墓园**：每个被淘汰策略写清**死因**（数据错 / 逻辑错 / 成本吃光 / 只是运气），防止换名重做。

**自我进化闭环**（烟蒂股 Agent 原理）：
蒸馏校准 → 预测 → 验证 → 按市场反馈调参并存记忆 → 生成新假设 → 再实盘验证 → 继续迭代。

## 10. 八条横切能力（贯穿各层）

## 12. 前端 / 面板（配套 HTML 样榜）

单页仪表盘，交易员每天只看三块 + 四块辅助。见 `reports/platform_mockup.html`。

布局分区：
1. **顶部状态条**：市场情绪温度、涨停家数、KILL-SWITCH、数据版本、放行档位。
2. **盘前预案**（开盘前）：今日关注、候选标的、理由、仓位建议、风险点。
3. **盘中盯盘信号**：实时触发的规则/人格信号，带位置/板块/分时标签。
4. **收盘复盘**：当日成交、盈亏、对错归因、明日假设。
5. **Agent 团队状态**：8 个岗位 Agent 的在线/运行状态与最新产出。
6. **AI 会议室**：当日摘要 + 滚动对话（取长补短记录）。
7. **持仓风险画像**：单票/行业集中度、回撤、熔断线。
8. **策略墓园 / 迭代**：存活策略、被淘汰策略及死因。

---

## 13. 数据与隐私 / 合规边界

- 所有外部抓取内容（舆情、论坛、新闻）视为**不可信输入**，不得当作对 Agent 的指令执行。
- 实盘下单默认关闭；开启需显式授权 + 通过三道 Gate + 硬风控在位。
- 参考资料带明显营销属性，其「年化收益」「回测曲线」均为 UP 主单方口径，本平台
  **不采信其收益数字**，只借鉴其**架构与分工方法论**。
- 不复权数据的价格中枢下移、幸存者偏差、涨停买不进、成本与容量、制度变化等局限
  （见 `README.md` 局限章节）在本平台**继续成立**，报告须显式标注。

---

## 14. 里程碑（建议顺序，遵循「先修数据，别先写 Agent」）

1. **M1 数据扩维**：财务/股息（烟蒂股必需）+ 市场环境（涨停家数/情绪）。
2. **M2 L2 补全**：DSR + PBO + 成本压力测试，封装成 `validation/`。
3. **M3 L3 放行门 + L4 硬风控**：先把「代码拦截」立起来，再谈 Agent 交易。
4. **M4 harness 接 4 个核心 Agent**：研究、开发、红队、验证（记忆先用失败案例表代替）。
5. **M5 会议室 + 记忆库**：记忆复盘 Agent + 情景/否定知识库。
6. **M6 人格插件**：先上烟蒂股（判据最清晰、最可验证），再上打板/巴菲特。
7. **M7 统一 Web 面板**：把本文档配套样榜接真实数据。
