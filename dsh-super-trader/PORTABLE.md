# Super Trader 0.8：安装与迁移

## 在哪里使用

安装后，DSH 左侧主菜单提供 **专家选股 / 个股分析 / 板块分析 / 量化因子预测 / 专家团队 / 自选股 / 研究记录 / 数据与设置**。所有页面在中间主区显示，不注册右侧栏。

日常流程：选专家（默认全A股）→ 专家自主探索目录、按需取证并各自选股 → 查看独立名单、交集、分歧与实际覆盖 → 研究个股/板块或继续趋势会诊。不是从本地量化库或统一基本面阈值预筛名单。专家调用可能计费，仅明确点击后开始，受预算限制，不承诺全市场逐股分析，也不发证券订单。

## 安装包包含什么

`.tgz` 包含 Host/Client 插件、后端 Python 源码、原量化计算模块、7 项运行依赖说明、原 MIT 许可证和源码校验清单。

**不包含** Python 解释器、第三方依赖、行情/模型密钥、个人数据库、1.6GB 历史日线、概率网格及可重建缓存。程序可以离开原仓库安装，不等于换一台机器就自动拥有历史研究数据。

## 新机器

1. 安装 Python 3.10+，在选定的 Python 环境安装包内 `runtime/requirements.txt` 的依赖。插件不会擅自联网运行 pip。
2. 在 DSH 插件管理安装本包 `.tgz`（或使用官方 `plugin_manager`）。不要直接修改 DSH profile 的包清单。
3. 必要时在启动 DSH 前设置 `ST_PYTHON`，指向装好依赖的解释器。
4. 在启动 DSH 前配置需要的路径（环境变量）：

| 变量 | 用途 |
|---|---|
| `ST_STATE_DIR` | 可写个人状态目录；默认当前 DSH profile 下 `super-trader-data`，没有 profile 则用户主目录下 `.super-trader` |
| `ST_STATE_DB` | 可选，覆盖 SQLite 状态库文件 |
| `SUPER_TRADER_DATA_ROOT` | 原始日线目录，保留原 `个股 / ETF / 指数` 数据格式 |
| `SUPER_TRADER_REPORT_DIR` | 原报告根目录；网格位于其 `fullfit/probability_grid.json` |
| `SUPER_TRADER_CACHE_DIR` | 可重建缓存目录，默认状态目录下 `cache` |
| `HITHINK_FINANCE_KEY_FILE` | 后端读取的同花顺密钥文件；也支持 `HITHINK_FINANCE_API_KEY` |
| `ST_BASE_URL` | 可选，已有本机 Super Trader 后端的 loopback URL |

不要在截图、代码、公开配置或聊天里填写密钥原文。便携模式不扫描相邻目录的默认密钥文件。专家会诊通过后端 `ST_MODEL_API_KEY` / `ST_MODEL_KEY_FILE` 明确配置模型；未配置会直接报503，不伪造团队意见，也不读出或复制DSH私有凭据。可选的DSH草稿使用DSH当前会话自身模型。

## 缺数据时的实际能力

- 没有日线：后端仍能启动，历史搜索为空，概率接口返回明确 503；不会伪造概率或生成样例行情。
- 有同花顺凭据和模型、没有本地日线/网格：仍可从真实A股目录开展专家自主选股，读取财报、估值、行情与日K；量化缺失不排除候选，量化和依赖本地历史的复盘保持不可用。
- 量化因子预测需要配置本地日线根目录（`SUPER_TRADER_DATA_ROOT`），按其下`个股/ETF/指数/*.csv`纳入批量任务，历史不足100根明确跳过，不生成假回测。单股查询/代码回测只做本地计算，不调用模型；**批量自主挖掘会真实调用已配置模型，可能计费**，仅明确点击后启动，有预算和取消。
- 没有行情凭据：状态页明确未配置；已有自选、记录及专家定义可以读取。`configured=true` 也不表示供应商鉴权/额度一定可用。
- 行情快照时间和历史信号截止日期分开显示；K线图默认前复权日K，不改变本地历史信号口径。

## 旧机器迁移

- 程序：携带 `.tgz`，在另一套兼容 DSH 中安装。
- 研究数据：另行复制日线与需要的报告，设置上述两个路径。缓存可重建，不必复制。
- 个人状态：保存旧数据库前停止旧后端，或使用 SQLite backup API 获取一致备份；不要只复制正在 WAL 模式写入的单个数据库文件。把备份放到新 `ST_STATE_DB`。原数据库不会被安装包覆盖。
- 凭据：在新机器单独安全配置；不随程序或个人研究导出打包。
- 兼容边界：本机 Windows 已做真实离仓启动/回收测试；其他操作系统没有实际验收，不承诺已通过。

源码 link 开发模式仍兼容完整 Super_Trader 仓库布局，不搬动现有状态库与密钥。`ST_REPO_ROOT` 是明确的开发源码位置覆盖，不是新机器的必需条件。
